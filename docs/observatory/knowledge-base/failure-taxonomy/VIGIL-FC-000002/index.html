Capability-Authority Separation

The system assumes that because it has the ability or tool access to do something, it is allowed to do it.

Immutable class ID
VIGIL-FC-000002
Semantic code
CAPABILITY_AUTHORITY_SEPARATION

Status
beta

Technical definition

A failure in which available capability, tool access, credentials, privileges, network or target reachability, inherited sessions, API availability, feature availability, or other action affordances are treated as sufficient authority for an action without separately establishing permission for the actor, target, action, and scope.

Recognition criteria

  • A capability, credential, session, network path, API, target, or execution pathway is technically available or reachable.
  • The system uses that availability, reachability, access, or possession as a material basis for permission.
  • Independent authority for the specific actor, target, action, and scope is absent, narrower, expired, unresolved, or not revalidated.

Exclusions

  • A permitted action is executed within an explicitly authorised scope.
  • The system merely detects that capability exists but does not infer permission from it.
  • A vulnerability exists but no AI or governance process converts capability into authority.

Supporting evidence

External sources supporting this Failure Class definition, boundary or recognition criteria.

  • OWASP Foundation · 2024-11-19 · authoritative guidance

    LLM06:2025 Excessive Agency

    Evidence note. OWASP distinguishes an agent's available functionality and downstream permissions from the minimum authority required for its intended operation, and calls for user-context execution, least privilege, approval and complete mediation. This directly supports the class boundary between technical capability and permission; it does not define every exercise of broad capability as unauthorised or establish the actor, target, scope or occurrence facts required by VIGIL.

  • IEEE Standards Association · 2024-07-05 · standards evidence

    IEEE 7009-2024, Annex A.3 / 7009-ASR-011

    Evidence note. EXTREQ-C64032FC58E84CBA requires a means to inhibit specified function execution when no authorization to execute is available. It independently supports the distinction between technical ability and authority; IEEE 7009 is fail-safe specific and does not define every capability-authority inference covered by VIGIL.
