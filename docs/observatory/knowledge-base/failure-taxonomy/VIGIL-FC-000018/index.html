Completion-Condition Mismatch

The system checks the wrong thing and treats that check as proof that the actual task is finished.

Immutable class ID
VIGIL-FC-000018
Semantic code
COMPLETION_CONDITION_MISMATCH
Failure family

Status
beta

Technical definition

A failure in which an internal milestone, intermediate state, local tool result, syntactic condition, or partial criterion is substituted for the externally relevant condition that defines task completion.

Recognition criteria

  • The task has an externally relevant completion condition.
  • A different internal, intermediate, local, or partial condition is satisfied.
  • The system treats satisfaction of the substitute condition as sufficient proof of overall completion.

Exclusions

  • The intermediate condition is explicitly the agreed completion condition.
  • The system accurately describes the result as an intermediate milestone.
  • The task fails before any completion representation is made.

    Specification gaming: the flip side of AI ingenuity

    Evidence note. DeepMind describes specification gaming as satisfying the literal specification of an objective without achieving the intended outcome, including obtaining reward without completing the intended task. This directly supports the structural distinction between a satisfied proxy or internal condition and the externally intended success condition; specification gaming is broader than, and does not itself define, VIGIL's completion-condition or completion-representation class.
