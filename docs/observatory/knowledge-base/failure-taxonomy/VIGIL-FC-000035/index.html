Material Work-State Persistence

Important work disappears or becomes unavailable when the session, process, or environment changes.

Immutable class ID

MATERIAL_WORK_STATE_PERSISTENCE

Status
beta

Technical definition

A failure in which material intermediate work, task decisions, dependency state, or resumable progress is not durably preserved across an interruption or transition for which continuation is required or reasonably represented as supported.

Recognition criteria

  • Material work state has been produced and is necessary for correct continuation.
  • An interruption, restart, handoff, expiry, or environment transition occurs.
  • The state is lost or unavailable because it was not preserved with the required durability.

Exclusions

  • The state was explicitly ephemeral and no continuation was required or represented.
  • The state persists but is restored inaccurately.
  • The work remains intact and only access to it is temporarily unavailable.

Supporting evidence

External sources supporting this Fidelity Class definition, boundary or recognition criteria.

  • Microsoft · 2026-08-10 · authoritative guidance

    Microsoft Agent Framework Workflows - Checkpoints

    Evidence note. Microsoft documents checkpoints as saved workflow state used to avoid lost progress and resume work after failure, pause or migration, including durable cross-process storage for production workflows. This directly supports preservation of resumable material work state across interruption; it is framework-specific guidance and does not establish that every transient intermediate state must be persisted or define VIGIL's materiality and represented-continuation thresholds.

  • ACM Computing Surveys · 2002-09-01 · research evidence

    A survey of rollback-recovery protocols in message-passing systems

    Evidence note. Rollback-recovery literature treats preserved checkpoints and logs as the basis for restoring material system state after failure. This independently supports persistence of work-relevant state across interruption; VIGIL separately requires that materially required work state be lost or detached in a governance-relevant workflow.
