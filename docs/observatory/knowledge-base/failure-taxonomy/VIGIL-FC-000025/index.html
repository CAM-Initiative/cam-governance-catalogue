Actor–Action Attribution Loss

An action is visible, but it is unclear which model, agent, tool, human, or automated process actually caused it.

Technical definition

A failure in which a material action or decision cannot be reliably attributed to the effective actor, agent, model, human, service, tool, policy, or orchestration component responsible for initiating or controlling it.

Recognition criteria

  • A material action or decision is observable.
  • Attribution to the effective initiating or controlling actor is necessary for review or accountability.
  • Available evidence cannot reliably establish that attribution or collapses distinct actors into one undifferentiated source.

Exclusions

  • The responsible actor is adequately attributable.
  • The issue is authorship provenance of content rather than operational responsibility for an action.
  • Multiple actors jointly contributed and the evidence accurately preserves the shared contribution.

Supporting evidence

External sources supporting this Failure Class definition, boundary or recognition criteria.

  • World Wide Web Consortium · 2013-04-30 · standards evidence

    PROV-DM: The PROV Data Model

    Evidence note. PROV-DM expressly models agents and responsibility relations, including attribution of an entity to an agent and association of an activity with an agent and role. It directly supports preserving actor–artefact and actor–activity attribution; VIGIL extends that structure to the failure case where effective operational responsibility for a material action cannot be established.

  • AAM Cyber · 2026-05-12 · authoritative guidance

    SDOS Runtime Governance Framework v1.10, control SDOS-AU-01

    Evidence note. EXTREQ-422283C001BAFEE1 requires a structured record for each governed tool invocation that includes agent identity and material execution metadata. It directly supports actor-action attribution in agentic tool workflows; SDOS is a private-sector framework and does not establish universal or statutory logging duties.
