Post-Verification State Integrity

The system verifies one version, changes it afterwards, and still calls the changed version verified.

Immutable class ID
VIGIL-FC-000019
Semantic code
POST_VERIFICATION_STATE_INTEGRITY
Fidelity family
Verification & Completion Integrity VIGIL-FF-0003
Status
beta

Technical definition

A failure in which content, state, configuration, code, data, or an execution artefact is materially changed after verification while retaining or inheriting the verification status of the earlier state without revalidation.

Recognition criteria

  • A specific state or artefact is verified.
  • A material mutation occurs after that verification.
  • The mutated state is represented or consumed as verified without a fresh check covering the mutation.

Exclusions

  • The post-verification change is immaterial to the verified property.
  • The changed state is reverified before reliance.
  • The system clearly invalidates the earlier verification status after mutation.

  • The MITRE Corporation · 2026-04-30 · authoritative guidance

    CWE-367: Time-of-check Time-of-use (TOCTOU) Race Condition

    Evidence note. CWE-367 describes the structural failure in which a resource changes after a check and before use, invalidating the check result. VIGIL uses this as a technical analogue for the check–mutation–reliance sequence; CWE-367 does not establish VIGIL's broader governance class for content, configuration, data, or assurance artefacts.

  • IEEE Standards Association · 2021-09-15 · standards evidence

    IEEE 7000-2021, clause 10.3(e)(8)

    Evidence note. EXTREQ-D999E91F3E053E85 requires verification and continued monitoring to identify when changed context or priorities require design revision. This supports invalidation of earlier verification after material change; it does not itself isolate mutation between verification and reliance.
