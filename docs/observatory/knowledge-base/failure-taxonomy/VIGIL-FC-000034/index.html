Continuity Anchoring

The work exists, but it is no longer reliably tied to the task, checkpoint, or context needed to resume it.

Immutable class ID
VIGIL-FC-000034
Semantic code
CONTINUITY_ANCHORING
Failure family
Continuity-State Integrity VIGIL-FF-0006
Status
beta

Technical definition

A failure in which material work state lacks or loses the stable identity, checkpoint, task binding, dependency binding, or reference needed to locate and resume the correct continuation state after interruption or transition.

Recognition criteria

  • Material state exists or is expected to support later continuation.
  • A stable anchor is required to bind that state to the correct task, checkpoint, dependency set, or continuation point.
  • The anchor is absent, lost, ambiguous, or detached, preventing reliable resumption.

Exclusions

  • The state is correctly anchored but its contents were not persisted.
  • The correct state is recoverable and only the user-facing label is inconvenient.
  • The failure concerns attribution of authorship rather than resumption of work.

Supporting evidence

External sources supporting this Failure Class definition, boundary or recognition criteria.

  • Microsoft · 2026-08-10 · authoritative guidance

    Microsoft Agent Framework Workflows - Checkpoints

    Evidence note. Microsoft's Agent Framework requires rehydrated workflows to preserve the topology and executor identities of the workflow that created the checkpoint, and states that changing those identities makes the rebuilt workflow incompatible with the checkpoint. This directly supports the need for a stable continuation anchor binding persisted state to the correct resumable workflow; VIGIL generalises that structural requirement beyond this framework.

  • ACM Computing Surveys · 2002-09-01 · research evidence

    A survey of rollback-recovery protocols in message-passing systems

    Evidence note. Elnozahy et al. survey checkpoint-based and log-based rollback-recovery protocols in which consistent checkpoints anchor system restoration. This independently supports the need for trustworthy continuity anchors; VIGIL's class applies the principle to governed work-state continuity rather than only distributed-system fault recovery.
