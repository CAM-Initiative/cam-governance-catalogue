VIGIL Observatory · VIGIL-INC-000045

Grok Build uploaded entire Git repositories to xAI storage

In July 2026, a researcher testing Grok Build v0.2.93 captured uploads of whole Git bundles to xAI storage, including tracked files the coding agent had been told not to read and the repository’s commit history. In one test, the agent was asked only to reply “OK”; the repository bundle was still transmitted. The researcher later observed that xAI had switched off the upload server-side on the tested account. The test used canary files and fake secrets; it did not establish that xAI trained on the uploaded code or exposed a real customer’s credentials.

Incident breakdown

In tests of Grok Build v0.2.93, a researcher captured the CLI sending a Git bundle with tracked files and repository history to xAI storage even when the task asked only for “OK” and the agent was not asked to inspect repository files.

Classified

The CLI sent tracked files beyond those the bounded coding task needed or the agent read, so task-local permission was extended to repository-wide storage transfer in the observed implementation.

The researcher later observed that xAI had disabled the upload server-side on the tested account; the observation did not establish the scope or permanence of the change across accounts.

Conclusion

The tested CLI expanded task-local repository access into a repository-wide external storage action. The controlled capture establishes a target-and-scope authority failure in that implementation; it does not by itself establish downstream misuse of the data or a quantified real-customer confidentiality harm. Later server-side disablement limits current generalisation, not the observed 0.2.93 behaviour. The retained target/scope failure is bounded to the captured implementation and task, without inferring real secret disclosure, training use or population-wide damage. Tested-account disablement is resolved recovery context rather than an affirmative fleet-wide success. Independent OECD assessment finds user-agency/scope safeguards Not aligned for the captured repository-wide transfer and repair Aligned only for the subsequently observed tested-account disablement. Model-development storage and human-subject data-consent requirements address different lifecycle/participation objects and remain audit-only. No real-secret exposure, training use or fleet-wide repair is inferred.

Governance significance

Permission to run a coding task in a repository does not itself cover bulk transmission of all tracked files and history. The upload path and retention setting need to be visible as distinct governed actions because an ordinary model-training opt-out did not stop the captured storage transfer in the test.
