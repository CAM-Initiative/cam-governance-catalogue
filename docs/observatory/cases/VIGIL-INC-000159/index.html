VIGIL Observatory · VIGIL-INC-000159

Cline prompt-injection and cache-poisoning chain enabled unauthorized npm package publication

Attacker-controlled GitHub issue text prompted Cline's Claude-powered triage agent to execute code, enabling poisoning of shared GitHub Actions cache state that later reached a privileged release workflow. The chain exposed an npm token and led to unauthorised publication of `cline@2.3.0`; Cline deprecated the version and revoked credentials. Cline reported no evidence that OpenClaw itself was malicious or that user data was exposed.

Incident breakdown

Cline's postmortem explains that any GitHub user could open an issue handled by a Claude-powered triage workflow with Bash access; attacker-controlled issue instructions could cause code execution, and the workflow's shared cache scope let poisoned state reach a nightly release workflow with publication secrets.

Classified

This clause preserves the connected prompt-execution, shared-cache and privileged-release pathway described in Cline's postmortem; the separate untrusted-content authority boundary is represented in clause 2.

Attacker-controlled issue text induced tool execution and crossed through shared cache state into a privileged release control plane.

Authority propagated from a public issue-triage workflow through cache state and nightly release credentials to npm publication.

Attacker-controlled issue content was treated as operative instruction rather than remaining non-authorising data.

Classified

Untrusted issue content was treated as operative instruction instead of remaining non-authorising data, allowing attacker-controlled text to direct consequential tool activity.

Post-incident evidence preserved the material instruction and release-path events needed to document the occurrence.

Classified

The retained post-incident evidence captured the material instruction, tool and release-path events needed to preserve the occurrence record.

The retained evidence allowed the material compromise chain to be reconstructed without repeating unnecessary exploit mechanics.

Classified

The retained evidence supported reconstruction of the compromise chain while the public rationale remains bounded and does not restate unnecessary exploit mechanics.

After the researcher publicly disclosed the workflow vulnerability, Cline removed the vulnerable workflows and rotated credentials, but deleted the wrong npm token. The exposed npm token remained active, while the organization-level token page showed zero active tokens and did not surface it.

Classified

The reported recovery action and verification signal addressed the wrong credential, establishing target-binding failure independently of the initial prompt-injection chain.

Cline states that recovery deleted the wrong npm token and used an organization-level view that did not surface the exposed token. The revocation action and clean-state signal were not bound to the actual compromised credential, which remained usable until the later publication.

On February 17, a third party used the still-active npm token to publish cline@2.3.0 with a postinstall script that globally installed OpenClaw, which Cline later described as a legitimate, non-malicious open-source project.

Reviewed — no current class applies

The package change and publication are reported; this clause does not infer that user systems were compromised beyond the reported software installation.

Cline published corrected version 2.4.0, deprecated 2.3.0 and revoked the token by 11:23 a.m. It reported that the occurrence was limited to the npm CLI package, no malicious code was delivered, and no user data was accessed or exfiltrated.

Reviewed — no current class applies

The response and impact bounds are those reported by Cline; this clause does not independently verify all user installations or infer zero exposure outside the reviewed audit.

Conclusion

Untrusted issue content crossed into a tool-enabled workflow and then propagated through shared infrastructure into release authority. The model interaction was one necessary link; cache design, token scope and release configuration were independently necessary. Prompt authority, control-plane propagation and captured reconstruction retain their roles. The recovery decision is also assessed as target-binding failure because the wrong token was deleted while the exposed token remained usable. Later correct revocation does not erase that interval; OpenClaw is not recast as malicious.

Governance significance

The case demonstrates that AI issue-triage agents must be isolated from shared build state and publication credentials, because prompt injection can become supply-chain authority through ordinary CI/CD mechanisms.
