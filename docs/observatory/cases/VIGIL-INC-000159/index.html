VIGIL Observatory · VIGIL-INC-000159

Cline prompt-injection and cache-poisoning chain enabled unauthorized npm package publication

A Cline GitHub issue-triage workflow introduced in December 2025 allowed untrusted issue content to direct a Claude-powered tool and exposed shared workflow state used by a more privileged release pipeline. Security research reported the weakness in January 2026 and publicly disclosed it on 9 February.

Cline removed the vulnerable workflows but mistakenly revoked a different npm credential, leaving the exposed token active. On 17 February, a third party used the active credential to publish an unauthorised Cline CLI release that caused unexpected installation of a legitimate third-party project.

Cline deprecated the release, revoked the token and published a corrected version within about eight hours. Cline found no malicious code delivery or user-data access; the identity or continuity of the original researcher and the later publisher is not established.

Incident breakdown

On 21 December 2025, Cline introduced a Claude-assisted GitHub issue-triage workflow with broad command execution on untrusted issue content. Security research subsequently demonstrated that attacker-written issue text could direct the tool and reach cache state shared with a privileged release workflow.

The vulnerable design was reported on 1 January 2026 and publicly disclosed on 9 February; the original report does not establish that the third party responsible for the later package publication was the same person as the reporting researcher.

Classified

Attacker-controlled issue text induced tool execution and crossed through shared cache state into a privileged release control plane.

Authority propagated from a public issue-triage workflow through cache state and nightly release credentials to npm publication.

Untrusted issue content was treated as operative instruction instead of remaining non-authorising data, allowing attacker-controlled text to direct consequential tool activity.

After the February 9 public disclosure, Cline removed the vulnerable workflows and rotated several credentials. During npm token revocation it removed the wrong token, then relied on an organisation-level management view indicating zero active tokens.

The actually exposed npm token remained active and usable.

Classified

Cline states that recovery deleted the wrong npm token and used an organization-level view that did not surface the exposed token. The revocation action and clean-state signal were not bound to the actual compromised credential, which remained usable until the later publication.

On 17 February 2026 at 03:26 Pacific Time, an unauthorised party used the still-active npm publishing credential to release Cline CLI version 2.3.0 with an extra postinstallation dependency installation. Cline's forensic comparison says the CLI binary was unchanged and the installed third-party project was legitimate, not malicious.

The release was unauthorised; its source does not establish malicious code delivery, user-data theft or compromise of the separately distributed IDE extensions.

Reviewed — no current class applies

By 11:23 Pacific Time on 17 February, Cline published corrected CLI version 2.4.0, deprecated the unauthorised version and revoked the compromised token. It later described completed workflow and credential hardening, including provenance-linked releases, while longer-term disclosure and independent audit work remained in progress.

Reviewed — no current class applies

Cline's later incident analysis cross-checked its workflow history, release channels, npm artefacts and credentials, preserving enough evidence to identify the vulnerable intake path, the incomplete token revocation and the subsequent unauthorised publication. One preserved evidentiary sequence supports both capture and reconstructability; these do not represent two further attacker actions.

Classified

The retained post-incident evidence captured the material instruction, tool and release-path events needed to preserve the occurrence record.

The retained evidence supported reconstruction of the compromise chain while the public rationale remains bounded and does not restate unnecessary exploit mechanics.

Conclusion

The documented chain crossed from untrusted issue text through AI tool execution and shared infrastructure into release authority. Security failed.

Bounded traceability, incident documentation and later repair are supported. The wrong-token revocation interval remains distinct, and full audit and monitoring arrangements remain unresolved.

Governance significance

The case demonstrates that AI issue-triage agents must be isolated from shared build state and publication credentials, because prompt injection can become supply-chain authority through ordinary CI/CD mechanisms.
