VIGIL Observatory · VIGIL-INC-000021

Microsoft personal-account sign-in failed for OpenAI users

OpenAI reported that users signing in with Microsoft personal accounts were unable to access ChatGPT or the API login flow on 5 June 2026. Users, including paid subscribers, reported token_exchange_failed errors. Some retained access on one device or route while failing on another, while another report said attempting Google sign-in did not restore access to the affected account. OpenAI applied mitigation and reported full recovery the same day.

Incident breakdown

OpenAI identified an incident in which users signing in with Microsoft personal accounts were unable to sign in.

Unresolved

The Microsoft-linked route is a material verification/authentication dependency, and fresh testimony shows existing paid entitlements blocked by token-exchange failure; however, the occurrence does not consistently establish absence of a proportionate cached, degraded or alternate access route.

The provider distinguishes the affected Microsoft personal-account route rather than collapsing materially different access causes into one misleading state.

OpenAI applied mitigation and then reported that impacted services had recovered.

Reviewed — no current class applies

The evidence shows route recovery, but it does not establish an authentication expiry, revocation, refresh, replacement or reauthentication state that failed to propagate across an active session.

The incident was described as affecting Microsoft personal-account sign-in rather than all account access.

Classified

The provider distinctly identified Microsoft personal-account sign-in as the affected route rather than representing the incident as a generic account, entitlement or platform state, preserving the material access-state distinction during failure.

Conclusion

The occurrence demonstrates why federated identity dependencies and fallback state must be represented separately from account validity. A failed identity route can block practical access to an otherwise existing account without implying suspension, revocation or entitlement loss. The governance question is therefore not merely whether sign-in failed, but whether a valid or unresolved entitlement remains practically reachable through a proportionate alternate path. The public evidence establishes the dependency failure but does not establish a uniform absence of such fallback across affected users. The access-state differentiation success is local to accurate route identification. The verification-dependency clause remains unresolved because fallback conditions vary; successful status discrimination does not establish continuity for every affected user. Independent external assessment supports source-bounded repair in the restoration stage. The stakeholder communication-plan outcome remains Boundary because its complete planning evidence is unavailable. The SDOS governance-degradation candidate is excluded on its specific trigger or publication timing, rather than voluntary status.

Governance significance

This incident provides a useful near-boundary case for Verification-Dependency Access Continuity. It shows that evidence of a paid entitlement plus failed federated verification can satisfy much of the class while still falling short if fallback availability is unresolved or heterogeneous. That boundary prevents VIGIL from treating every identity-provider outage as a verification-dependency governance failure.
