Conclusion

The post-update chatbot responses and DPD’s disablement are documented. The task-specific disengagement aligns with the contemporary mechanism requirement. The exact update mechanism and prior assurance state are not established; later framework versions are not applied retrospectively.

Governance significance

Customer-facing systems need release testing, behavioural monitoring and a rapid rollback or disable path because an update can change both service quality and public-facing conduct. DPD's intervention limited the duration, but the occurrence shows that post-deployment controls are part of the product's governance boundary.
