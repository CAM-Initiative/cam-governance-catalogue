ChatGPT Work context limit ended a VIGIL adjudication/consolidation thread before material work was durably published

During a ChatGPT Work workflow reconciling role-aware VIGIL adjudication from `fix/inc-001-050-adjudication-matrix` into `integration/consolidate-divergent-branches`, the user explicitly instructed the agent to commit material work as it progressed. Durable GitHub state nevertheless lagged behind the conversation: the architecture changes and INC-000001–000002 had reached the branch, while later adjudication and consolidation state remained in the Work thread. The interface then reported that the conversation was too long to continue. A recovery pass found the branch safe at commit 500700e8 but recorded that most later role-aware adjudication had not been published, so the workflow had to be reconstructed before consolidation could continue.

Incident breakdown

A live ChatGPT Work adjudication thread reached its context limit and could not continue; recovery showed that material adjudication completed after the last GitHub checkpoint had not been durably published.

Classified

The work existed and was needed for continuation, the context boundary interrupted the workflow, and unpublished state was unavailable from the durable repository checkpoint afterward.

The task, branch and last durable repository checkpoint remained identifiable; the failure was that later material work contents were never durably persisted. Continuity Anchoring excludes a case where the continuation anchor is known but the state contents themselves were not persisted.

Compliance

No occurrence-specific external requirement assessment is published for this Case File.

Conclusion

The bounded failure is not merely that a long conversation ended. Material work state necessary for correct continuation remained dependent on the conversational context after substantive adjudication had been performed. When the context boundary forced termination, the durable repository state represented only an earlier checkpoint, so later completed work was unavailable for resumption and had to be reconstructed. That is a direct Material Work-State Persistence failure. The evidence does not support a broader claim about hidden product architecture or universal ChatGPT behaviour. The retained work-state persistence failure concerns actual completed material decisions missing from the durable checkpoint, not inability to identify the branch or continuity anchor. Later reconstructed blobs are not a count of lost work. No eligible reviewed FC-derived candidate or independent source-identified admitted requirement is established by this evidence; absence of an external finding does not reduce the occurrence-level persistence failure.

Governance significance

For CAM, the occurrence demonstrates that reasoning completion and durable work completion are distinct states. Long-running agentic or governance workflows should checkpoint material decisions to a recoverable store before a context boundary can terminate the execution surface, and should preserve a reconstructable handoff when continuation cannot proceed in the current context.
