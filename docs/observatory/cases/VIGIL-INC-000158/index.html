Moltbook database exposure revealed private communications and API authentication tokens

Wiz researchers found that Moltbook’s public database connection lacked row-level security. They reported access to about 35,000 email addresses, 4,060 private conversations and approximately 1.5 million authentication tokens.

Some messages held third-party credentials. The tokens could permit agent impersonation; that possible misuse was separate from the researchers’ database access.

Wiz contacted the maintainer on 31 January 2026. Initial fixes restricted sensitive reads, but researchers could still change a live post.

Further fixes blocked writes and secured newly discovered tables by 01:00 UTC on 1 February. Wiz said it could no longer revert its test post after write access was blocked; the team later deleted the post.

Wiz also reported deleting the data accessed during research and verification.

Conclusion

Missing database restrictions exposed private information and credentials. Researchers also demonstrated a live integrity effect after the first repair.

Iterative fixes and the blocked attempt to revert the post support bounded remediation verification. They do not prove that prior access was fully discovered or that all copied information was recovered.

The record does not establish an AI or governance process using technical reachability as an authority basis.

Governance significance

The case shows that AI-agent platforms remain dependent on conventional application-security controls for credentials, private communications and account integrity.
