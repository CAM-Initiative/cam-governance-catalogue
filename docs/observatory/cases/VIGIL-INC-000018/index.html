VIGIL Observatory · VIGIL-INC-000018

ChatGPT’s new app blocked Enterprise users without Codex permissions

OpenAI reported that some Enterprise users whose workspaces did not have Codex access enabled were unable to log in to the new ChatGPT application after installing it, receiving a codex_cli_workspace_disabled error even though ChatGPT Classic remained available. OpenAI released a fix on 18 July 2026, but the problem then recurred for some Enterprise users before the provider later reported full recovery.

Users had to update the app to receive the first fix; the recurrence was reported before the final recovery notice.

Conclusion

The governance mechanism is a scope error in access-state representation: a component-level Codex permission determined whether the user could enter a broader ChatGPT application surface despite the user's broader ChatGPT access remaining available through Classic. The recurrence after an initial fix adds a restoration-quality lesson: correcting the immediate access path is not sufficient unless the relevant entitlement variants are regression-tested so the narrower component state cannot again redefine broader application availability.

The observed access-state distinction is Not aligned. The public report does not establish whether an upstream entitlement representation supplied a wrong trigger to a correctly operating gate or the activation predicate itself applied to the wrong scope.

A separate control-activation finding is therefore held. Classic remained an actual practical fallback.

A disabled component permission is not evidence of an unavailable or inconclusive verifier, so no verification-dependency outcome is inferred. External framework scope and action-specific implementation remain unresolved; no requirement finding follows from either role.

Independent occurrence-level external assessment finds affirmative, source-bounded repair in the reported restoration stage. Relevant communication/incident-process requirements remain Boundary where the decisive plan or implementation record is not public.

Requirements addressing a different technical object, lifecycle or source date remain audit-only; voluntary adoption is not a gate.

Governance significance

This incident demonstrates why entitlement systems need compositional, separately inspectable state rather than a single opaque available/unavailable result. It also shows why recovery testing must cover the affected permission combinations: a fix that appears successful but allows the same cross-surface collapse to recur has not yet restored stable access-state integrity.
