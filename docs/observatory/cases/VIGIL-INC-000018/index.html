VIGIL Observatory · VIGIL-INC-000018

ChatGPT’s new app blocked Enterprise users without Codex permissions

OpenAI reported that some Enterprise users whose workspaces did not have Codex access enabled were unable to log in to the new ChatGPT application after installing it, receiving a codex_cli_workspace_disabled error even though ChatGPT Classic remained available. OpenAI released a fix on 18 July 2026, but the problem then recurred for some Enterprise users before the provider later reported full recovery.

Incident breakdown

Enterprise users without Codex RBAC enabled received a Codex workspace-disabled error when opening the new ChatGPT application.

Classified

A narrower Codex RBAC state was used to represent availability of the broader new ChatGPT app even though ChatGPT Classic remained accessible, collapsing materially distinct access conditions at the new-app boundary.

ChatGPT Classic remained available as a temporary alternative.

Reviewed — no current class applies

The functioning fallback demonstrates that the broader ChatGPT access state differed from the new application's Codex-coupled state.

After OpenAI released a fix, the issue recurred for some Enterprise users before final recovery.

Reviewed — no current class applies

The recurrence shows that the same access-state coupling reappeared after the first fix and therefore remained materially relevant until final recovery.

Users unable to access the new application retained access through ChatGPT Classic.

Classified

Classic remained a practical alternative to the Codex-coupled new app, but the reported Codex RBAC-disabled state is a component permission restriction rather than an evidenced temporarily unavailable or inconclusive verification pathway. The occurrence materially distinguishes fallback availability from fulfillment of the verification-noncompletion success conditions; it establishes neither FC-048 failure nor success.

Conclusion

The governance mechanism is a scope error in access-state representation: a component-level Codex permission determined whether the user could enter a broader ChatGPT application surface despite the user's broader ChatGPT access remaining available through Classic. The recurrence after an initial fix adds a restoration-quality lesson: correcting the immediate access path is not sufficient unless the relevant entitlement variants are regression-tested so the narrower component state cannot again redefine broader application availability. The canonical result is an access-state differentiation failure plus a verification-dependency boundary. Classic availability is an affirmative practical fallback, but disabled Codex permission is an established component restriction, not an evidenced temporarily unavailable or inconclusive verifier. It therefore does not establish the success-recognition conditions for Verification-Dependent Access Continuity. The earlier success role is preserved in the audit and corrected to ambiguous boundary without denying the fallback benefit. External framework scope and action-specific implementation remain unresolved; no requirement finding follows from either role.

Governance significance

This incident demonstrates why entitlement systems need compositional, separately inspectable state rather than a single opaque available/unavailable result. It also shows why recovery testing must cover the affected permission combinations: a fix that appears successful but allows the same cross-surface collapse to recur has not yet restored stable access-state integrity.
