VIGIL Observatory · VIGIL-INC-000009

ChatGPT started image generation before the user authorised execution

A user-posted X report preserved in the CAM Initiative Registry shows ChatGPT being asked to rewrite prompt material while the user says “Again, do not touch image generator”; immediately below, the interface displays a Thinking/image-generation state. The user reported that mentioning “art”, “prompt”, or “image” repeatedly caused the image generator to fire, forced app reloads, switched the visible model from GPT-5.5 to “5.4 Thinking”, and that uploading an image without follow-up text could activate generation or crash the app.

Incident breakdown

The preserved screenshot shows a request to rewrite prompt material together with the explicit instruction “Again, do not touch image generator”, followed by a displayed Thinking/image-generation state.

Classified

The authorised task was text rewriting with image generation explicitly excluded, yet the interface entered a materially different image-generation action state without fresh authority.

The corrective instruction and reported recurrence make continuity-state validity a plausible boundary, but the artefact does not establish that a continuity transition preserved or inherited the invalid image-tool state rather than the action being independently re-triggered by later lexical or attachment cues.

Image-generation capability was available and activated outside the authorised text-rewrite scope, but the artefact does not establish capability itself as the permission basis; this materially distinguishes capability-authority collapse from scope transposition.

The accompanying post states that the image generator fires whenever “art”, “prompt”, or “image” is mentioned, forces a reload each time, and switches the visible model without the user's choice.

Unresolved

The recurrence and repeated recovery/reset burden support a sticky-state interpretation, while the partial capture leaves open whether the state is inherited or independently re-triggered.

Each recurrence still crosses from the user's authorised conversational task into a materially different image-generation action scope without a fresh authority basis.

The workflow used image-generation capability even though the authorised task was limited to rewriting text.

Reviewed — no current class applies

Image-generation capability was available and used outside the authorised text-rewrite scope, but the evidence does not establish that capability itself was treated as the permission basis.

Conclusion

The occurrence engages both action-scope authority and continuity-state validity. First, permission to discuss or rewrite prompt text did not authorise a materially different image-generation action. Second, once the unwanted image-generation trajectory had emerged, the user's explicit corrective instruction should have invalidated or reset that trajectory for subsequent continuation. The fact that the captured interaction still enters the image-generation state, together with the report that this happened whenever relevant words were mentioned and required repeated reloads, supports a provisional Continuity-State Validity analysis. The evidence remains insufficient to claim a specific router, memory or model-state implementation. The action-scope failure is bounded to the captured interaction, with a capability-authority ambiguous boundary and a material unresolved continuity-state clause. The occurrence is therefore partially adjudicated; it does not support a blanket system failure or invariant-held conclusion. The unresolved sticky-state versus fresh lexical-trigger distinction is preserved rather than forced into a continuity mapping. External candidates yield no finding: the EU bias-processing permission postdates this capture, model-development duties do not govern this operational interaction, and runtime-framework adoption and human-subject participation remain unestablished.

Governance significance

This incident illustrates a dual governance requirement for multimodal systems: action authority must remain bounded to the user's authorised scope, and interaction/tool state must remain validity-bounded across conversational continuation. An explicitly rejected mode should not remain governing merely because it was previously active, nor should lexical mentions silently reinstate it without renewed authority.
