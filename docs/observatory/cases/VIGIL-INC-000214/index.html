VIGIL Observatory · VIGIL-INC-000214

ARTEX agents exploited stolen ConnectWise application access across Microsoft 365 tenants

In October 2026, Microsoft reported that attackers it identifies as Storm-0940 used ARTEX, a multi-agent AI penetration-testing framework, against organisations. From 10 to 14 October, a password-spray campaign produced more than 151,000 failed sign-ins across 327 accounts at eight organisations, with no successful authentication in that observed sample.

After ConnectWise Cloud Backup application identities were compromised, ARTEX-assisted attackers attempted access to more than 2,250 Microsoft 365 tenants. Microsoft found successful sign-ins and some follow-on account, application credential and permission changes in affected environments.

ConnectWise disclosed unauthorised access to application identities on 16–17 October, then revoked affected access and suspended Cloud Backup jobs, archive access and restores, with related security and management services also interrupted. Its recovery and testing continued through at least 25 October.

Microsoft did not establish that every targeted tenant was breached or that each authentication resulted in data theft.

Incident breakdown

On 10–14 October, actors generated 151,000+ unsuccessful logons targeting 327 accounts at eight organisations. Microsoft observed no successful token or Graph event in that sample.

Reviewed — no current class applies

Compromised ConnectWise application credentials were used by ARTEX-assisted attackers for sign-in attempts reaching more than 2,250 Microsoft 365 tenants.

Classified

Agents used stolen ConnectWise application credentials to attempt external tenant operations without those tenants granting the attacker's access; available access was treated as operational permission.

Compromised application credentials were used outside ConnectWise’s authorised application operation. Existing tenant grants did not authorise the threat actor to hold those credentials.

In some customer environments Microsoft observed successful authentication followed by Graph reconnaissance, application credential changes and privilege or persistence actions.

Classified

AI-assisted Graph actions used technical application privileges to make or attempt changes in tenants where the criminal operator lacked independent authority.

Microsoft observed follow-on application credential changes in affected environments. These are distinct custody-changing modifications, not proof that every targeted tenant lost customer data.

Microsoft separately reports changes involving identities, groups and privileged roles in some affected environments. These protected directory-state modifications are distinct from stolen or added authentication material and do not imply customer-content theft.

Microsoft cautions that a tenant being targeted or successfully authenticated does not automatically prove customer data was accessed or stolen.

Reviewed — no current class applies

ConnectWise confirmed unauthorised application-identity access and disabled affected app connections, including certificate revocation, on 17 October.

Reviewed — no current class applies

Classified

Current taxonomy recognition tests (reference only)

Shared class criteria are not occurrence evidence. The recorded adjudication version may differ.

  • Identifiable material serves an authentication or authorisation function, or contains the protected secret content needed to exercise that function, in an AI-mediated system or dependent infrastructure.
  • An independently evidenced custody boundary governs who or what may hold, receive, disclose, modify or replace the material in the assessed lifecycle stage.
  • Occurrence evidence demonstrates exposure outside that boundary, unauthorised acquisition, or unauthorised custody-changing modification or replacement. Demonstrated retrievability of protected secret content is sufficient without proof of subsequent credential use.

Exclusions

  • Class scope exclusion (all results): The material is only a non-secret identifier, public connection identifier, public verification key or public client configuration that is intended to be available in the assessed context. A separately exposed secret or unauthorised protected-information operation requires its own assessment.
  • Class scope exclusion (all results): The issue concerns only coherent propagation of expiry, revocation, refresh or replacement into sessions and dependent operations. Assess Authentication-State Continuity unless a separate custody property is evidenced.
  • Not aligned exclusion: Credential handling or delegation is validly authorised and preserves the applicable custody boundary. Mere credential possession or ordinary authorised use is not a custody defect.
  • Not aligned exclusion: Only a theoretical vulnerability, unverified secret classification, unusable placeholder or unsuccessful attempt is shown; protected authentication material is not demonstrated outside custody.
  • Not aligned exclusion: Material is already invalid and no residual secret-protection or custody obligation is independently established. Do not assume every expired token remains a usable secret.
  • Class scope exclusion (all results): The only property is the scope of an action performed using a credential, without a distinct custody issue. Assess the applicable authority or action class.

Conclusion

AI agents acting on attacker instructions used compromised application credentials to exercise technical access across otherwise separately governed customer tenants. The observed capability-to-authority boundary was crossed at downstream account and identity operations, but no independent agent rebellion, jailbreak or objective drift is established.

ConnectWise revoked affected credentials, and in its monitored environment no further successful attack activity was reported. That is a bounded protective outcome.

The ensuing interruption of Cloud Backup and linked services was deliberate containment of the breach, not an attacker-commanded service shutdown. The record does not treat 2,250 attempted tenants as confirmed victims of data theft.

Microsoft reports abuse of compromised application credentials and observed follow-on credential changes in affected environments. Those authentication objects and modifications crossed authorised custody.

The separate unsuccessful password-spray sample and successful sign-ins alone do not prove customer-data theft. Microsoft reports follow-on changes involving identities, groups and privileged roles in affected customer environments.

Those are protected directory-information modifications by the threat actor, separate from credential custody. The finding does not infer mailbox or file theft from sign-in events, and it does not apply to every targeted tenant.

Governance significance

The incident distinguishes multi-agent attacker-controlled automation, stolen integration credentials, tenant-granted application trust, actual downstream authorisation, monitoring, containment and service availability. It also demonstrates that credential-based access by an external AI agent can reach real customer state without valid authority from the customer, while the defensive recovery affects important operational services.
