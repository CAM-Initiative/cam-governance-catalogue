VIGIL Observatory · VIGIL-INC-000095

Compromised Mistral SDK package executed credential-harvesting payload on import

Mistral reported that the Mini Shai-Hulud supply-chain attack on TanStack resulted in compromised Mistral npm and PyPI SDK versions being published. The compromised PyPI package `mistralai==2.4.6` executed malicious code when client modules were imported on Linux, downloading a background payload that harvested credentials from common locations.

Mistral reported no impact to its global infrastructure and removed the affected releases. Its updated advisory says the compromised npm releases referenced a missing file, preventing their malicious path from running.

The working PyPI payload was Linux-specific. Mistral later marked mitigation and closed its investigation.

The repository advisory distinguishes client-module imports from a bare namespace import. It also records quarantine of the Python project.

TanStack supply chain attack affecting Mistral SDK packages

Mistral AI · 2026-05-12

Mistral identifies compromised SDK releases, publication windows and a PyPI import-time payload that launched credential-harvesting code, while reporting no impact to Mistral's global infrastructure.

Scope: The security advisory diagnoses the same software-supply-chain occurrence but does not quantify customer execution or successful credential exfiltration.

VIGIL relationship: VIGIL treats the occurrence as a software-supply-chain package-provenance and release-integrity failure in ordinary-language governance terms, while retaining the Incident as unclassified under Failure Taxonomy 0.6.5 because no current selectable class precisely encodes malicious package-distribution substitution.

Incident breakdown

Mistral says the TanStack worm compromised a developer device and led to malicious SDK releases. Its investigation found no impact to global infrastructure.

Reviewed — no current class applies

Compromised npm SDK versions were published on 11 May and removed early on 12 May. PyPI mistralai 2.4.6 was published and removed on 12 May.

Trusted package identities carried attacker content.

Classified

The malicious Python release used the Mistral SDK package identity. The repository advisory identifies no matching release tag, commit or workflow and says the upload bypassed the normal publishing pipeline.

The attributed package origin therefore differed materially from the supported contribution history. This affected developer trust and reuse.

A genuine distribution endpoint does not make the attacker’s contribution an authorised Mistral release. This finding is bounded to that Python release; valid workflow provenance elsewhere in the campaign does not prove code safety or establish the same publishing route here.

The PyPI version ran malicious code on Linux import and launched a detached credential-harvesting process. The repository advisory specifies imports under mistralai.client on Linux; a bare namespace import does not trigger the loader.

Taxonomy coverage gap

The updated advisory says the compromised npm releases referenced a missing file, so their malicious path could not run. It still instructed users to remove them.

Reviewed — no current class applies

Aikido separately detected malicious npm versions. Mistral removed its affected releases within hours, but the public accounts do not link one operative Mistral control to detection and withdrawal.

The repository advisory also records quarantine of the Python project. That protective action can be assessed separately from the causal route connecting the external detection to provider withdrawal.

Classified

Mistral withdrew the compromised SDK versions within hours. The Python project was also quarantined.

These measures acted on the identified malicious distribution and limited further availability through the affected release channel. This establishes a bounded protective effect for release containment.

It does not establish customer credential recovery, removal from private caches or the effectiveness of every earlier safeguard. Aikido’s detection need not be proved to have caused Mistral’s action to assess the withdrawal itself.

Mistral marked mitigation on 13 May and closed its investigation on 14 May. It advised affected users to clean systems, rotate accessible secrets and review cloud logs and retained package copies.

Conclusion

The compromised Python release represented attacker content under the Mistral SDK identity without matching legitimate release lineage. Its source attribution is Not aligned.

The release withdrawal and Python-project quarantine are Aligned for the bounded purpose of containing further distribution through the affected channel. The external detection and provider response remain causally distinct in the available accounts.

No particular pre-publication safeguard is presumed to have failed. The malicious executable asset also presents a software-integrity property beyond the origin-attribution and response findings.

The selectable taxonomy does not fully represent that property without additional evidence of an authority-conversion mechanism. The nonfunctional npm path remains distinct from the working Linux Python path.

Customer cleanup and credential exposure remain unknown. The independent AI software-security and repair assessments are preserved.

Harm Impact: The publisher confirms actual malicious SDK versions were released through its distribution channel. Those persisted releases changed the expected integrity of a real software asset, establishing the S2 integrity minimum.

Customer restoration burden remains unknown.

Governance significance

AI-system governance includes the developer infrastructure surrounding a model. Compromised package provenance can expose credentials and downstream systems before the model is ever invoked, making third-party build dependencies, release integrity and incident response part of the assurance boundary.
