VIGIL Observatory · VIGIL-INC-000095

Compromised Mistral SDK package executed credential-harvesting payload on import

Mistral reported that the Mini Shai-Hulud supply-chain attack on TanStack resulted in compromised Mistral npm and PyPI SDK versions being published. The compromised PyPI package `mistralai==2.4.6` executed malicious code on import, downloading a background payload that harvested credentials from common locations. Mistral reported no impact to its global infrastructure and removed the affected releases.

Conclusion

Trusted package-distribution channels carried malicious code into an AI software development kit. The governance problem is therefore not a model output but the integrity of the software supply chain through which developers receive AI tooling, including package provenance, release controls and the authority of third-party maintainers. Aikido’s external detection and Mistral’s removal show a distinct post-publication response stage. The available accounts do not establish that a specific Mistral pre-publication control was required and failed, or that the external monitoring was the operative control that caused removal. Package identity substitution and the link between external detection and provider removal remain ambiguous. Import-time malware is distinct from GAI output; removal does not prove a prepublication control duty or global compromise. The AI software-distribution security outcome is Not aligned. Withdrawal of the affected releases is Aligned with the repair requirement. Monitoring and security-review processes remain Boundary where their operative evidence is not available.

Governance significance

AI-system governance includes the developer infrastructure surrounding a model. Compromised package provenance can expose credentials and downstream systems before the model is ever invoked, making third-party build dependencies, release integrity and incident response part of the assurance boundary.
