VIGIL Observatory · VIGIL-INC-000119

Nx s1ngularity malware weaponized local AI coding CLIs during credential-harvesting supply-chain attack

Attackers stole an Nx npm publishing token through a GitHub Actions injection flaw. Nx later reported that they deleted branches and workflow runs to conceal traces during this compromise.

They published malicious Nx package versions on 26 August 2025. The package post-install malware directly harvested credentials and sensitive files and also attempted to invoke locally configured Claude, Gemini and Amazon Q command-line tools with prompts designed to identify additional sensitive files for exfiltration.

Results and stolen credentials were uploaded to public GitHub repositories. GitGuardian identified 2,349 distinct secrets in 1,079 affected repositories during the initial phase, with more than 1,100 still valid at the time of analysis, and later observed 10,767 private repositories made public, exposing 82,901 secrets including 11,168 then-valid secrets.

The AI-assisted path was only one component of the attack: GitGuardian reported that only 95 of 366 targeted systems produced the requested AI-generated inventory file, and Wiz separately found substantial refusal, configuration and workspace-restriction failure rates across the invoked AI tools. Subsequent response included package removal, repository removal and credential revocation.

Wiz also observed a later repository-upload phase affecting one organisation.

Incident breakdown

Nx reported that attackers exploited a GitHub Actions injection flaw, obtained a publishing token through a malicious workflow, and deleted branches and workflow runs to conceal traces before publishing infected packages on 26 August 2025.

Reviewed — no current class applies

Installed malware attempted to invoke locally configured Claude, Gemini and Amazon Q tools to inventory sensitive files. Researchers observed both assistance and refusal or execution failure; GitGuardian found the requested inventory on 95 of 366 targeted systems.

Classified

Attacker-supplied prompts became ordinary local CLI inputs, materially testing source-authority separation, but the preserved evidence does not establish a common lower-authority source state that the heterogeneous tools promoted into instruction authority.

Some tools successfully enumerated locally reachable files, but success alone does not establish that any common tool treated technical reachability as permission; the multi-vendor evidence materially distinguishes capability from authority without resolving the inference mechanism.

The malware directly collected credentials and uploaded stolen material to public GitHub repositories. AI-assisted discovery was an additional route; GitGuardian initially identified 2,349 distinct secrets in 1,079 repositories.

Current taxonomy recognition tests (reference only)

Shared class criteria are not occurrence evidence. The recorded adjudication version may differ.

Failure-side conditions

  • The system receives or retrieves content from a source whose authority is lower than, different from, or unresolved relative to the action being considered.
  • The content is treated as operative instruction or authority rather than as data, evidence, context, or material for analysis.
  • No independent authority check validly establishes that the source may authorise the affected action.

Success-side conditions

  • Non-authorising material enters a context where it could influence an operative instruction.
  • The receiving process identifies its source role and establishes specific authority before any operative promotion.
  • Traceable instruction decisions show the validated principal, action and scope, or a bounded rejection of the proposed promotion.

Exclusions

  • A system merely quotes, summarizes, classifies, or reasons about untrusted instructions without obeying them.
  • The source is genuinely authorised for the specific action and scope.
  • The event is only a content-quality or factual-accuracy problem.

Current taxonomy recognition tests (reference only)

Shared class criteria are not occurrence evidence. The recorded adjudication version may differ.

Failure-side conditions

  • A capability, credential, session, network path, API, target, or execution pathway is technically available or reachable.
  • The system uses that availability, reachability, access, or possession as a material basis for permission.
  • Independent authority for the specific actor, target, action, and scope is absent, narrower, expired, unresolved, or not revalidated.

Success-side conditions

  • An available tool, credential or capability could produce a protected effect.
  • Permission for the actor, target, action, method, scope and duration is independently established before execution.
  • Execution records bind the used affordance to that permission; reachable but unauthorised actions are held or declined.

Exclusions

  • A permitted action is executed within an explicitly authorised scope.
  • The system merely detects that capability exists but does not infer permission from it.
  • A vulnerability exists but no AI or governance process converts capability into authority.

Conclusion

Malware tried to repurpose local AI tools after the initial package compromise. Some tools assisted sensitive-file discovery; many refused or failed.

Those successful runs support bounded failures in harmful-query handling and security under misuse. Direct malware theft and the aggregate repository exposure remain separate from the AI-assisted path.

Harm Impact: The campaign exposed sensitive credentials and private repositories. The recorded quantities support substantial confidentiality harm.

Direct malware theft also contributed: only 95 of 366 sampled AI-tool targets produced the requested inventory. The full campaign exposure is not allocated exclusively to AI-assisted discovery.

Governance significance

The incident demonstrates a distinct agent-security surface: malware can discover and invoke trusted local AI developer tools, attempt to bypass their permission and safety boundaries, and use successful sessions to extend reconnaissance beyond static malware logic. It also shows why outcome assessment must preserve partial refusal and failure rates rather than treating all targeted AI tools as uniformly compliant.
