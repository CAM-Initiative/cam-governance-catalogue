Authentication-State Continuity

Authentication changes propagate coherently to sessions and dependent operations before protected work continues.

Technical definition

The property by which expiry, revocation, refresh, recovery, replacement and reauthentication propagate coherently and promptly into active sessions and dependent operations, keeping effective access consistent with represented state and rebinding renewed authority before protected continuation.

Governing invariant

Expiry, revocation, refresh, recovery, credential replacement, and reauthentication must propagate coherently and promptly to every dependent session and operation. Stale authentication must not continue to authorise action, and renewed authority must be correctly rebound before protected continuation.

Invariant held

Success condition

Available occurrence evidence establishes the following bounded outcome: Effective sessions and operations reflect the changed authentication state promptly and renewed access is rebound before protected continuation.

Positive recognition

  • Authentication expires, is revoked, renewed or recovered during dependent operations.
  • Effective sessions and operations reflect the changed authentication state promptly and renewed access is rebound before protected continuation.
  • Authentication events, session state and protected operations demonstrate coherent propagation and renewed authority binding.

Failure established

Failure condition

Authentication changes underneath the interaction, but the session does not transition coherently with it.

A failure in which expiry, revocation, refresh, recovery, or replacement of authentication state is not propagated coherently to the active session and its dependent operations, leaving effective access inconsistent with the session's represented state.

Failure recognition

  • An authentication-state transition occurs or is required.
  • An active session or dependent operation retains a materially inconsistent authentication or access state.
  • The inconsistency impairs correct continuation, termination, reauthentication, or access enforcement.

Exclusions from failure recognition

  • The session transitions coherently and merely requires the user to authenticate again.
  • A validly authenticated actor lacks authority for the requested action.
  • Credentials are exposed or stolen without a session-state continuity failure.
